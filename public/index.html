Rose nodes

Host a Rose node

Lend your PC or server to this Rose: it runs game sessions on your hardware, so more people can play at once. Your machine connects out to this server, so there are no ports to open, and players never learn your address (or you theirs).

What you need

  • Linux on x86_64 (or arm64) with Docker and the compose plugin.
  • Binder in the kernel, which Android needs: binderfs built in, or the binder_linux module (Ubuntu/Debian: linux-modules-extra, or binder_linux-dkms). WSL2 and many stock VPS kernels need a custom kernel or module; container-based VPSes (OpenVZ/LXC) can't run it at all.
  • GPU optional: an AMD or Intel GPU (/dev/dri) makes games smoother; without one, sessions render on the CPU. The uhid module is recommended for controllers in console games.
  • Per player: about 2.5 GB RAM and 2 CPU threads for an Android game, about 6 GB and 4 threads for Switch homebrew, plus 2 GB for the system. The node sizes itself from your machine.
  • Disk: 20 GB or more (Android image, game downloads cache).
  • Bandwidth: about 4 to 6 Mbit/s of upload per player, plus game downloads.
  • Windows 10 (1809 or later) or Windows 11, 64-bit: Home, Pro or Enterprise. Android needs a Linux kernel, so the installer sets up Multipass (Canonical's Ubuntu VM manager, through winget) and runs the node in a small Ubuntu VM.
  • Virtualization on in the BIOS/UEFI (Intel VT-x or AMD-V/SVM), and the Windows feature Virtual Machine Platform: the installer offers to turn it on (then restart Windows and run it again). Multipass 1.17 or later uses Windows' built-in hypervisor on every edition, Home included; older Multipass needed Hyper-V (Pro/Enterprise) or VirtualBox (Home).
  • No GPU acceleration: games in the VM render on the CPU, so a PC hosts fewer players than the same PC on Linux, and heavy 3D games run slower.
  • RAM and CPU: 9 GB RAM and 4 CPU threads at least. The VM takes half the RAM (leaving Windows at least 4 GB, reserved while it runs) and all threads but 2; change it with -MemoryGB and -Cpus.
  • Expect: 16 GB, 8 threads: an 8 GB / 6 CPU VM, about 2 players. 32 GB, 12 threads: 16 GB / 10 CPUs, about 4 players.
  • Disk: 30 GB for the VM (-DiskGB). Bandwidth: about 4 to 6 Mbit/s of upload per player.
  • macOS 14 Sonoma or later (13 Ventura with an older Multipass), on Apple Silicon (M1 or later) or Intel. Android needs a Linux kernel, so the installer sets up Multipass (with Homebrew if you have it, otherwise Canonical's installer) and runs the node in a small Ubuntu VM.
  • Apple Silicon: the VM is ARM (arm64), so Android games built for ARM, which is most of them, run natively. Games with only x86 code and Switch homebrew are never sent to your Mac.
  • No GPU acceleration: games in the VM render on the CPU, so expect fewer players than on a Linux PC, and heavy 3D games run slower.
  • RAM and CPU: 9 GB RAM and 4 CPU cores at least (8 GB Macs are too small). The VM takes half the RAM (leaving macOS at least 4 GB, reserved while it runs) and all cores but 2; change it with --memory and --cpus.
  • Expect: 16 GB, 10 cores: an 8 GB / 8 CPU VM, about 2 players. 32 GB, 12 cores: 16 GB / 10 CPUs, about 4 players.
  • Disk: 30 GB for the VM (--disk). Bandwidth: about 4 to 6 Mbit/s of upload per player.

Before you host

        
    
          
  • Sessions are privileged Android containers on your machine, started through Docker by code from this server. Only join a Rose you trust.
    • 
          
  • Games' own internet traffic goes out from your connection and IP address.
    • 
          
  • Players can't install their own apps or files on your machine unless you turn that on (NODE_ALLOW_UPLOADS=1).
    • 
          
  • The owner can disable or remove your node at any time, and you can stop it at any time; running sessions then end.
    • 
        

      


      

        
For players

        
When a game runs on a community host, the launch screen and the in-game menu say “Hosted by” and the host's name. That game runs on that person's computer, which can see what you type into it: don't type passwords into games on community hosts.
